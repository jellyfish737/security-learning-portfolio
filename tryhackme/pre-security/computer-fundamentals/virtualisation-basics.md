## 概要 **/ Overview**

なぜ仮想化が現代のITを支え、効率を高め、環境を安全に隔離するのかを学ぶ

## メモ **/ Notes**

- **Virtualisation（仮想化）**
    - 1台の物理サーバー上で複数の独立したシステムを動作させる技術
    - 各システムは独自のOS、アプリケーション、設定を持つことができる
    - サーバーのリソースを効率的に活用できる
- **物理サーバー（Host Machine）**
    - 仮想マシンを実行する実際のコンピュータ
    - CPU、メモリ、ストレージなどのリソースを仮想マシンへ提供する
- **仮想マシン（Virtual Machine / VM）**
    - 物理サーバー上で動作する独立したコンピュータ環境
    - 実際のPCと同様にOSやアプリケーションを実行できる
    - 他の仮想マシンと分離されているため安全性が高い
- **ハイパーバイザー（Hypervisor）**
    - 仮想マシンを作成・管理するソフトウェア
    - 仮想化環境の中核となる技術
    - 物理リソースを各仮想マシンへ割り当てる役割を持つ
- **Type 1 Hypervisor**
    - ハードウェア上で直接動作するハイパーバイザー
    - 高性能で効率が良く、企業サーバー環境で利用される
    - ホストOSを必要としない
- **Type 2 Hypervisor**
    - 既存のOS上で動作するハイパーバイザー
    - 導入が容易で学習や検証環境に適している
    - VirtualBox や VMware Workstation が代表例
- **Host OS**
    - ハイパーバイザーや仮想マシンを実行する親OS
    - Type 2 Hypervisor で利用される
- **Guest OS**
    - 仮想マシン内部で動作するOS
    - Windows、Linuxなど自由に選択できる
- **サンドボックス環境**
    - ファイルやプログラムを安全に検証するための隔離環境
    - マルウェア解析や不審ファイルの調査で利用される
    - ホスト環境への影響を最小限に抑えられる
- **マルウェア解析における仮想化**
    - 不審なファイルを安全に実行・分析できる
    - ホストとゲストの通信を制限することで感染リスクを低減できる
    - 異なるOSを使用することで影響範囲を限定できる

---

#### コンテナ技術

- **Container（コンテナ）**
    - アプリケーションと必要なライブラリをまとめて実行する軽量な実行環境
    - 仮想マシンよりも少ないリソースで動作する
    - 起動が高速で運用効率が高い
- **VMとコンテナの違い**
    - VMはOSごと仮想化する
    - コンテナはホストOSのカーネルを共有する
    - コンテナは軽量で高速だが、ホストOSへの依存がある
- **Docker**
    - コンテナの作成・配布・実行を簡単にするプラットフォーム
    - 開発環境と本番環境の差異を減らせる
    - 現在のクラウドやDevOps環境で広く利用されている

---

#### 学んだこと

- 仮想化により1台の物理サーバーで複数のシステムを効率的に運用できる
- 仮想マシンは独立したOS環境を提供し、安全な検証環境として利用できる
- ハイパーバイザーは仮想化環境を管理する重要なコンポーネントである
- Type 1は本番環境向け、Type 2は学習・検証向けとして利用されることが多い
- マルウェア解析では隔離された仮想環境を利用することで安全性を高められる
- コンテナはVMより軽量で高速だが、ホストOSのカーネルを共有するという違いがある
- Dockerはコンテナ運用を効率化する代表的なプラットフォームである
