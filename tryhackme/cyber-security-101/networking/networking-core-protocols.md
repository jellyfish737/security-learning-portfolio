## 概要 **/ Overview**

TCP/IPの主要なプロトコルについて学ぶ

## 実施内容 **/ Practical Work**

- 仮想環境で操作をしながら設問に答える。
- AttackBox 上の FTP クライアント `ftp` を使用して、`MACHINE_IP` 上の FTP サーバーへアクセスし、`flag.txt` を取得してください。見つかったフラグは何ですか？
    - ftp 10.146.175.159
    - ftp> get flag.txt
    - ftp> quit
    - cat flag.txt
    - フラグが確認できた

- telnet を使用して 10.146.175.159 の POP3 サーバーへ接続してください。4番目のメッセージに含まれているフラグは何ですか？
    - Username: `linda`
    - Password: `Pa$$123`
    - telnet 10.146.175.159 110
    - USER
    - PASS Pa$$123
    - LIST でメッセージを確認
    - RETR 4 でメールの内容を確認
    - メール本文にフラグが確認できた

## 気づき・考察 **/ Key Insights & Analysis**

- DNS・HTTP・SMTPなどはすべて平文で通信されることが多く、マルウェア解析では「どのドメインへ通信しているか」「何を送受信しているか」をそのまま観測できる重要な手がかりになる。
- ポート番号の知識は、ログや通信キャプチャから「どのプロトコルが使われているか」を即座に推定するための基本スキルになる。

## メモ **/ Notes**

### DNS (Domain Name System)

- **DNS**
    - ドメイン名とIPアドレスを対応付ける仕組み
    - 人間が覚えやすいドメイン名を利用できるようにする
    - OSIモデルのアプリケーション層（レイヤー7）で動作する
    - 通常はUDPポート53を使用し、大きな応答などではTCPポート53を使用する

#### 主なDNSレコード

- **Aレコード**
    - ドメイン名をIPv4アドレスへ対応付ける
    - 例：
        - `example.com → 172.17.2.172`
- **AAAAレコード**
    - ドメイン名をIPv6アドレスへ対応付ける
    - IPv6版のAレコード
- **CNAMEレコード**
    - ドメイン名の別名（エイリアス）を設定する
    - 例：
        - `www.example.com → example.com`
- **MXレコード**
    - メール受信を担当するメールサーバーを指定する
    - メール配送に利用される

#### DNSの重要ポイント

- Webサイトへアクセスする前にDNSで名前解決が行われる
- DNSがなければIPアドレスを直接入力する必要がある
- インターネット利用時に最も頻繁に使われるプロトコルの一つ

### WHOIS

- **WHOIS**
    - ドメイン登録情報を確認するためのサービス
    - ドメイン所有者や登録情報を調査できる

確認できる情報

- 登録者情報
- 登録日
- 更新日
- 有効期限
- ネームサーバー情報

#### 活用例

- OSINT（公開情報調査）
- ドメイン所有者の確認
- フィッシングサイト調査

---

### HTTP / HTTPS

- **HTTP (HyperText Transfer Protocol)**
    - WebブラウザとWebサーバーが通信するためのプロトコル
    - Webページ閲覧の基盤となる
- **HTTPS**
    - HTTP通信をTLSで暗号化したもの
    - 通信内容の盗聴や改ざんを防ぐ

#### よく使われるポート

- HTTP：80
- HTTPS：443

#### 主なHTTPメソッド

- **GET**
    - データを取得する
- **POST**
    - データを送信する
- **PUT**
    - データを作成または更新する
- **DELETE**
    - データを削除する

#### イメージ

- GET → 情報を見る
- POST → 新規登録する
- PUT → 情報を書き換える
- DELETE → 情報を削除する

---

### FTP (File Transfer Protocol)

- **FTP**
    - ファイル転送専用のプロトコル
    - クライアントとサーバー間でファイルの送受信を行う

#### 主な用途

- ファイルアップロード
- ファイルダウンロード
- サーバー管理

#### 主なコマンド

- `USER`
    - ユーザー名を送信
- `PASS`
    - パスワードを送信
- `RETR`
    - ファイルをダウンロード
- `STOR`
    - ファイルをアップロード

#### ポート番号

- TCP 21（制御通信）

#### 特徴

- ディレクトリ一覧取得とファイル転送は別接続で行われる
- 現在は暗号化されていないため利用が減少している

---

### SMTP (Simple Mail Transfer Protocol)

- **SMTP**
    - メール送信に使用されるプロトコル
    - メールクライアントとメールサーバー間の通信を担当する
    - メールサーバー同士の配送にも利用される

#### 主なコマンド

- `HELO` / `EHLO`
    - 通信開始
- `MAIL FROM`
    - 送信者指定
- `RCPT TO`
    - 受信者指定
- `DATA`
    - メール本文送信開始
- `.`
    - 本文終了

#### イメージ

- 郵便局へ手紙を出す仕組みに近い
- 「誰から誰へ送るか」を指定して配送する

---

### POP3 (Post Office Protocol Version 3)

- **POP3**
    - メールサーバーからメールを取得するためのプロトコル
    - 基本的にメールをローカルへダウンロードする

#### 特徴

- シンプルな構造
- サーバー容量を節約しやすい
- 複数端末での同期には不向き

#### 主なコマンド

- `USER`
- `PASS`
- `LIST`
- `RETR`
- `DELE`
- `QUIT`

#### イメージ

- 郵便受けから手紙を取り出すイメージ

---

### IMAP (Internet Message Access Protocol)

- **IMAP**
    - メールをサーバー上で管理しながら利用するプロトコル
    - 複数デバイス間でメール状態を同期できる

#### 特徴

- メールをサーバー上に保持する
- 既読状態を同期できる
- スマートフォンとPCで同じ状態を共有できる

#### 主なコマンド

- `LOGIN`
- `SELECT`
- `FETCH`
- `MOVE`
- `COPY`
- `LOGOUT`

#### POP3との違い

| POP3 | IMAP |
| --- | --- |
| ダウンロード中心 | 同期中心 |
| 単一端末向き | 複数端末向き |
| サーバー容量を節約できる | サーバー容量を多く使用する |
| 既読状態を共有しない | 既読状態を共有する |

---

### プロトコルの全体像

インターネット利用時には複数のプロトコルが連携して動作している。

1. DNSでドメイン名をIPアドレスへ変換
2. HTTP/HTTPSでWebサイトへアクセス
3. FTPでファイル転送
4. SMTPでメール送信
5. POP3またはIMAPでメール受信

#### 覚えておきたいポート番号

| プロトコル | ポート |
| --- | --- |
| DNS | 53 |
| HTTP | 80 |
| HTTPS | 443 |
| FTP | 21 |
| SMTP | 25 |
| POP3 | 110 |
| IMAP | 143 |

### 学習して特に重要だと感じたポイント

- DNSは「ドメイン名をIPアドレスへ変換する電話帳」
- HTTP/HTTPSはWeb通信の基本
- FTPはファイル転送専用プロトコル
- SMTPはメール送信
- POP3とIMAPはメール受信
- 実際のインターネット通信は複数のプロトコルが連携して成り立っている
