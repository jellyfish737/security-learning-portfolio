## 概要 **/ Overview**

自動設定からパケットの宛先へのルーティングまで、ネットワークプロトコルについて学ぶ

## 気づき・考察 **/ Key Insights & Analysis**

- ARP通信は同一LAN内の“名簿交換”のような役割で、ここが改ざんされる（ARPスプーフィング）と通信の盗聴や中間者攻撃が成立するため、MACアドレスの変化や不自然な応答は重要な検知ポイントになる。
- ICMP（ping/traceroute）は攻撃者の偵察でも頻繁に使われるため、大量のpingやTTLを変えた連続通信はスキャンや内部探索の兆候として注目される。
- tracerouteは通信経路の可視化により「どのISP・どの国・どのネットワークを経由したか」を推定できるため、C2サーバーや外部通信の経路分析に役立つ。
- ARP・DHCP・ICMP・NATはいずれも“日常通信そのもの”なので、攻撃者は特別な手口ではなく通常の通信に紛れる。だからこそ正常動作を理解していないと異常検知ができない。

## メモ **/ Notes**

#### Network Configuration

- **IP Address**
    - ネットワーク上のデバイスを識別するための住所
    - 同じネットワーク内でも重複しないように割り当てられる
    - 例：`192.168.1.100`
- **Subnet Mask**
    - IPアドレスのうち、どこまでがネットワーク部分かを示す
    - 同じネットワークに属する機器を判別するために使用される
    - `255.255.255.0` は `/24` と表記できる
- **Default Gateway**
    - 他のネットワークへ通信する際の出口
    - 通常はルーターのIPアドレスが設定される
    - 宛先が同じネットワーク内に存在しない場合、ゲートウェイへ転送される
- **DNS Server**
    - ドメイン名をIPアドレスへ変換する仕組み
    - 人間が覚えやすい名前で通信できるようにする
    - 例：
        - `google.com`
        - `github.com`

---

#### DHCP (Dynamic Host Configuration Protocol)

- **DHCP**
    - IPアドレスを自動的に割り当てるプロトコル
    - 手動設定の必要がなく、家庭や企業ネットワークで広く利用されている
    - UDPを利用する
        - サーバー：UDP 67
        - クライアント：UDP 68
- **DORA Process**
    - DHCPがIPアドレスを割り当てる際の4ステップ
    1. **Discover**
        - クライアントがDHCPサーバーを探す
    2. **Offer**
        - サーバーが利用可能なIPアドレスを提案する
    3. **Request**
        - クライアントが提案を受け入れる
    4. **Acknowledge**
        - サーバーが正式にIPアドレスを割り当てる
- **覚え方**
    - DORA = Discover → Offer → Request → Acknowledge

---

#### ARP (Address Resolution Protocol)

- **ARP**
    - IPアドレスからMACアドレスを調べるプロトコル
    - 同一ネットワーク内で通信する際に利用される
- **なぜ必要か**
    - 通信にはIPアドレスだけでなくMACアドレスも必要
    - Ethernetフレームには宛先MACアドレスが必要になる
- **通信の流れ**
    - ARP Request
        - 「192.168.1.1 を持っているのは誰？」
    - ARP Reply
        - 「私です。MACアドレスは○○です」
- **ポイント**
    - ARPはIPやUDPを使わず、Ethernetフレーム上で直接通信する

---

#### ICMP (Internet Control Message Protocol)

- **ICMP**
    - ネットワークの状態確認やエラー通知に利用されるプロトコル
    - ネットワーク診断で非常に重要

#### ping

- 相手ホストとの接続確認を行う
- ICMP Echo Request を送信
- ICMP Echo Reply が返ってくるか確認する

確認できる内容

- 相手が起動しているか
- 通信経路に問題がないか
- 応答速度（RTT）

---

#### traceroute

- パケットが目的地へ到達するまでの経路を調査する
- Windowsでは `tracert`
- Linuxでは `traceroute`

確認できる内容

- どのルーターを経由しているか
- どこで通信が遅延しているか
- どこで通信が失敗しているか

---

#### TTL (Time To Live)

- **TTL**
    - パケットが通過できるルーター数の上限
    - 無限ループを防ぐための仕組み
- **動作**
    - ルーターを1台通過するごとにTTLが1減少
    - TTLが0になるとパケットは破棄される
- **関連プロトコル**
    - ICMP Time Exceeded
- **活用例**
    - tracerouteはTTLを利用して経路を特定している

---

#### Routing

- **Routing**
    - パケットを目的地まで届けるための経路選択
    - ルーターが担当する
- **ルーターの役割**
    - IPアドレスを確認する
    - 最適な経路を選択する
    - パケットを次のネットワークへ転送する
- **イメージ**
    - 郵便局が手紙を最適な配送ルートへ振り分ける仕組みに近い

---

#### Routing Protocols

- **OSPF**
    - ネットワーク全体の構成を把握して最適経路を計算する
    - 大規模企業ネットワークでよく利用される
- **EIGRP**
    - Cisco独自のルーティングプロトコル
    - 帯域幅や遅延などを考慮して経路を選択する
- **BGP**
    - インターネット全体で利用されるルーティングプロトコル
    - ISP同士が経路情報を交換する
- **RIP**
    - ホップ数を基準に経路を選択する
    - シンプルだが大規模環境には不向き

---

#### NAT (Network Address Translation)

- **NAT**
    - プライベートIPアドレスをパブリックIPアドレスへ変換する技術
- **目的**
    - 限られたパブリックIPアドレスを効率よく利用する
- **メリット**
    - 1つのパブリックIPで複数端末がインターネットへ接続できる
    - IPv4アドレスの節約につながる
- **例**
    
    ```
    PC1 → 192.168.1.10
    PC2 → 192.168.1.20
    PC3 → 192.168.1.30
    
    ↓ NAT
    
    Public IP → 203.0.113.10
    ```
    
- **ポイント**
    - 家庭用ルーターのほとんどがNATを利用している

---

#### 通信の流れ（全体像）

- ネットワークへ接続するとDHCPがIPアドレスを取得する
- 通信相手をDNSで名前解決する
- ARPでMACアドレスを取得する
- IPパケットを作成する
- TCPまたはUDPで通信する
- ルーターが経路を決定する
- NATが必要に応じてアドレス変換する
- ICMPで通信確認やトラブルシューティングを行う
