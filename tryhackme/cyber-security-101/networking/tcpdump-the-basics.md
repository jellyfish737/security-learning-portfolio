## 概要 **/ Overview**

Tcpdump を使用してパケットを保存、フィルタリング、表示する方法について学ぶ

## 実施内容 **/ Practical Work**

- 仮想環境でtcpdumpを実行しながら設問に答える。。
- `traffic.pcap` の中で ICMP プロトコルを使用しているパケットはいくつありますか？
    - tcpdump -r traffic.pcap icmp -n

- MACアドレス `192.168.124.137` を問い合わせたホストの IP アドレスは何ですか？
    - tcpdump -r traffic.pcap arp  dst host 192.168.124.137 -n
    - 07:18:29.940761 ARP, Request who-has 192.168.124.137 tell の後に答えのIPを確認できた

- 最初の DNS クエリに現れるホスト名（サブドメイン）は何ですか？
    - tcpdump -r traffic.pcap port 53 -c 5 -n
    - 合計5つ現れたことを確認。そのうち一番最初のもので正解！

- TCP Reset（RST）フラグのみが設定されているパケットはいくつありますか？
    - tcpdump -r traffic.pcap "tcp[tcpflags] == tcp-rst" -n 2>/dev/null | wc -l
    - 正解の数字がダイレクトに返ってきた

- 15000バイトより大きいパケットを送信したホストの IP アドレスは何ですか？
    - -r traffic.pcap greater 15000 -n

- ARP リクエストを送信したホストの MAC アドレスは何ですか？
    - tcpdump -r traffic.pcap arp -e -n
    - 答えとなるMACアドレスを確認できた
    - まずは、答えとなるMACアドレスから ff:ff:ff:ff:ff:ff にARTリクエストが送られて、特定のMACアドレスから返答があることをログ上で確認できた

## 気づき・考察 **/ Key Insights & Analysis**

- tcpdump を使うことで、マルウェアが外部C2サーバへ通信している痕跡や、不審なDNSクエリを「実際のパケット」として確認できると分かった。ログだけでは見えない通信内容を観察できる点が重要だと感じた。
- `host` や `port` フィルタを使うことで、膨大な通信の中から「怪しい通信だけ」を効率よく絞り込めることが、フォレンジック調査で非常に役立つと理解した。

## メモ **/ Notes**

- tcpdump
    - Linux/Unix環境で利用できるパケットキャプチャツール
    - ネットワーク通信をリアルタイムで監視・記録できる
    - GUIのWiresharkと異なり、CLIで動作するためサーバー調査でもよく利用される
- ネットワークインターフェース指定 (`i`)
    - どのNIC（ネットワークインターフェース）を監視するか指定する
    - `i any` で全インターフェースを監視可能
    - `ip a` コマンドで利用可能なインターフェースを確認できる
- パケット保存 (`w`)
    - キャプチャした通信を `.pcap` ファイルとして保存する
    - 保存したファイルは Wireshark で後から解析できる
    - インシデント調査や証跡保全でよく利用される
- パケット読込 (`r`)
    - 保存済みの `.pcap` ファイルを読み込んで解析する
    - 過去の通信ログを調査する際に利用する
- キャプチャ件数制限 (`c`)
    - 指定した件数だけパケットを取得する
    - 不要な大量キャプチャを防げる
- 名前解決無効化 (`n`, `nn`)
    - DNS名やサービス名への変換を無効化する
    - 調査時は `nn` を使うことが多い
    - 不要な名前解決による通信発生を防げる
- 詳細表示 (`v`, `vv`, `vvv`)
    - パケットの詳細情報を表示する
    - レベルが高いほど多くの情報を確認できる

---

### よく使うフィルタ

- ホストフィルタ (`host`)
    - 特定のIPアドレスやホストとの通信だけを取得する

```
tcpdump host192.168.1.10
```

- 送信元ホストフィルタ (`src host`)
    - 特定の送信元からの通信だけを取得する

```
tcpdump src host192.168.1.10
```

- 宛先ホストフィルタ (`dst host`)
    - 特定の宛先への通信だけを取得する

```
tcpdump dst host192.168.1.10
```

- ポートフィルタ (`port`)
    - 特定ポートの通信だけを取得する

```
tcpdump port443
```

- プロトコルフィルタ
    - TCP、UDP、ICMPなど特定プロトコルのみ取得する

```
tcpdump tcp
tcpdump udp
tcpdump icmp
```

---

### 論理演算子

- AND
    - 複数条件を同時に満たす通信を取得する

```
tcpdump host1.1.1.1 and tcp
```

- OR
    - どちらかの条件に一致する通信を取得する

```
tcpdump udp or icmp
```

- NOT
    - 条件に一致しない通信を取得する

```
tcpdump not tcp
```

---

### パケット表示形式

- Quick表示 (`q`)
    - 最低限の情報のみ表示する
- Ethernetヘッダ表示 (`e`)
    - MACアドレスを確認できる
    - ARPやDHCP調査で有用
- ASCII表示 (`A`)
    - パケット内容を文字列として確認できる
    - HTTPなど平文通信の確認に便利
- Hex表示 (`xx`)
    - パケットを16進数で表示する
    - 詳細解析向け
- Hex + ASCII表示 (`X`)
    - 16進数と文字列を同時に表示する

---

### よく使うコマンド例

- SSH通信を確認

```
tcpdump-i any tcp port22
```

- DNS通信を確認

```
tcpdump-i any udp port53
```

- HTTPS通信を保存

```
tcpdump-i eth0 tcp port443-w https.pcap
```

- 名前解決を無効化して表示

```
tcpdump-i any-nn
```

- 保存済みpcapを確認

```
tcpdump-r capture.pcap
```
