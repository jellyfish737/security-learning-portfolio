## 概要 **/ Overview**

ログとは何か、そして効果的な調査のためにログを分析する方法について学ぶ

## 実施内容 **/ Practical Work**

- 仮想環境でハンズオンをしながら、設問に答える。
- Event Viewerのハンズオン。
    - このシステム上で最後に作成されたユーザーアカウント名は何ですか？
        - フィルター機能を利用し、イベントID：4720「ユーザーアカウントが作成された」で検索
        - AccountNameを確認
            - hacked
        
    - このアカウントを作成したユーザーアカウントは何ですか？
        - 上記のイベントの詳細画面から、Subject Account Nameを確認する。
            - Administrator
    - このユーザーアカウントが有効化された日はいつですか？（形式: M/D/YYYY）
        - 上記のイベントの詳細画面から、Logged の日付を確認する。
            - 6/7/2024
    - このアカウントでは、パスワードリセットも行われましたか？（形式: Yes/No）
        - フィルターで以下のように検索。
            - イベントID: 4724 「アカウントのパスワードをリセットしようとする試行が行われた」
            - Computers: CHANGE-MY-HOSTNAME （イベント詳細画面から確認できる）
        - 検索すると、同じ6/7日付で4724のログあり。
            - 答えは、Yes

- Web サーバーアクセスログファイルのハンズオン。
    - URL: `"/contact"` に対して最後に GET リクエストを送信した IP は何ですか？
        - grep "/contact" access.log
            - 10.0.0.1
        
        ```jsx
        root@ip-10-48-107-115:~/Rooms/logs# grep "/contact" access.log
        10.0.0.1 - - [06/Jun/2024:13:54:44] "GET /contact HTTP/1.1" 500 "-" "Mozilla/5.0 (Macintosh; Intel Mac OS X 10_12_3) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/58.0.3029.110 Safari/537.36"
        ```
        
    - IP: `"172.16.0.1"` による最後の POST リクエストはいつ行われましたか？
        - grep "172.16.0.1" access.log | grep "POST"
            - 06/Jun/2024:13:55:44
        
        ```jsx
        root@ip-10-48-107-115:~/Rooms/logs# grep "172.16.0.1" access.log | grep "POST"
        172.16.0.1 - - [06/Jun/2024:13:55:44] "POST /contact HTTP/1.1" 500 "-" "Mozilla/5.0 (Macintosh; Intel Mac OS X 10_12_3) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/58.0.3029.110 Safari/537.36"
        ```
        
    - 質問 2 の回答に基づき、その POST リクエストはどの URL に対して行われましたか？
        - 先ほどのログを見る
            - /contact

## 気づき・考察 **/ Key Insights & Analysis**

- Webアクセスログには IP、URL、HTTPメソッド、User-Agent など多くの情報が残るため、攻撃者の行動パターン分析に役立つと分かった。特に POST リクエストは、ログイン試行やデータ送信に関係する可能性があり、注意して見るべきだと思った。
- 攻撃者は痕跡を消そうとするが、完全には消し切れないケースも多いと学んだ。複数のログを時系列で組み合わせることで、断片的な情報から全体像を復元できるのがフォレンジックの面白さだと思った。

## メモ **/ Notes**

- Logs（ログ）
    - システムやユーザーの行動が記録された「デジタル上の足跡」
    - 攻撃調査やフォレンジックで重要な証拠になる
- Security Logs（セキュリティログ）
    - ログイン成功・失敗、ユーザー作成、権限変更などを記録
    - 不正アクセス調査で特に重要
- System Logs（システムログ）
    - OS やハードウェア、ドライバ関連のイベントを記録
    - システム障害や異常動作の原因調査に役立つ
- Application Logs（アプリケーションログ）
    - アプリケーション内部の動作やエラーを記録
    - アプリ固有の問題解析に利用される
- Audit Logs（監査ログ）
    - ユーザー操作や設定変更履歴を記録
    - コンプライアンスや内部不正調査で重要
- Network Logs（ネットワークログ）
    - 通信元・通信先・接続情報などを記録
    - 不審通信や C2 通信の発見に役立つ
- Access Logs（アクセスログ）
    - Web サーバーへのアクセス情報を記録
    - 攻撃者のアクセス履歴や行動分析に利用できる
- Windows Event Viewer
    - Windows のログを GUI で確認できるツール
    - Event ID を利用して特定イベントを効率的に検索できる
- Event ID
    - Windows イベントを識別する番号
    - 例:
        - 4624 → ログイン成功
        - 4625 → ログイン失敗
        - 4720 → ユーザー作成
- Web Access Log
    - Web サーバーへのリクエスト履歴
    - IP、HTTP Method、URL、Status Code、User-Agent などが含まれる
- HTTP GET
    - Web ページ閲覧などの取得リクエスト
    - 攻撃者の探索行動確認にも使える
- HTTP POST
    - ログイン情報送信やデータ送信で利用される
    - データ送信や不正操作の痕跡確認に重要
- User-Agent
    - 使用 OS やブラウザ情報を示す文字列
    - 攻撃ツールや自動化アクセスの識別ヒントになる
- grep
    - 特定文字列をログから検索する Linux コマンド
    - 大量ログから必要情報を絞り込める
- less
    - ログをページ単位で閲覧する Linux コマンド
    - 巨大ログの確認時に便利
- cat
    - ファイル内容を表示する Linux コマンド
    - ログ確認や複数ログ結合で利用できる
- Log Analysis（ログ分析）
    - ログから異常や攻撃痕跡を探す作業
    - 単体ログではなく、複数ログを時系列で見ることが重要
- Forensics（フォレンジック）
    - 攻撃後に証拠を収集・分析する調査手法
    - ログは攻撃者の行動復元に欠かせない情報源
