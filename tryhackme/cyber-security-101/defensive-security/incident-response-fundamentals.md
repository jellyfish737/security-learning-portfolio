## 概要 **/ Overview**

サイバーセキュリティにおけるインシデント対応の手法を学ぶ

## 実施内容 **/ Practical Work**

- 設問に答える。
    - セキュリティチームが、インシデント発生後にマシンのインターネット接続を無効化しました。これは SANS IR ライフサイクルのどのフェーズですか？
        - containment
    - NIST のどのフェーズが、SANS IR ライフサイクルの「Lessons Learned」フェーズに対応していますか？
        - Post Incident Activity

## 気づき・考察 **/ Key Insights & Analysis**

- インシデント対応は「マルウェアを削除して終わり」ではなく、封じ込め・根絶・復旧・再発防止まで含めて一連の流れとして考える必要があると理解できた。
- Playbook のように対応手順を事前に決めておくことで、実際の攻撃発生時に慌てず対応できることが分かった。特に複数端末が同時に感染した場合は、標準化された対応が重要だと感じた。

## メモ **/ Notes**

- Incident（インシデント）
    - 「セキュリティ上の問題が実際に発生した状態」
    - 単なる警告ではなく、実害や侵害の可能性がある状態を指す
    - 例：マルウェア感染、情報漏えい、不正アクセス
- Event（イベント）
    - システム上で発生した単なる「記録」や「動作ログ」
    - すべてのイベントが危険というわけではない
    - 例：ログイン、ファイル作成、通信開始
- Alert（アラート）
    - セキュリティ製品が「怪しい」と判断して通知したもの
    - ただし、アラート＝攻撃確定ではない
    - 人間による分析が必要
- False Positive（誤検知）
    - 「危険に見えたが、実際は正常だった」ケース
    - セキュリティ運用では頻繁に起きる
    - 例：バックアップ通信を不正通信と誤認
- True Positive（正検知）
    - 「実際に危険だった」ケース
    - 本当に対応が必要なインシデント
- Phishing（フィッシング）
    - ユーザーを騙して悪意あるファイルやURLを開かせる攻撃
    - 初学者が最初に遭遇しやすい攻撃手法
    - 「メールを信用しすぎない」が基本
- Malware（マルウェア）
    - システムへ悪影響を与える悪意あるプログラム
    - 実行ファイル、Office文書、スクリプトなど様々な形で侵入
    - 「ダウンロード」と「実行」は別問題である点が重要
- Threat Vector（侵入経路）
    - 攻撃者が侵入に利用した経路
    - どこから侵害されたかを特定する考え方
    - 例：メール添付、USB、脆弱性、RDP
- IOC（Indicator of Compromise）
    - 「侵害された痕跡」
    - フォレンジックやインシデント対応で超重要
    - 例：怪しいIP、ハッシュ値、不審なプロセス
- Timeline Analysis（タイムライン分析）
    - 「いつ何が起きたか」を時系列で整理する調査
    - フォレンジックの基本中の基本
    - 感染開始→実行→通信→拡散、を追跡できる
- Containment（封じ込め）
    - 被害拡大を防ぐフェーズ
    - まず「止血」するイメージ
    - 例：LAN切断、アカウント停止
- Eradication（根絶）
    - マルウェアや攻撃痕跡を削除する工程
    - 「隔離しただけ」では終わらない
- Recovery（復旧）
    - システムを正常状態へ戻す工程
    - バックアップ復元や再構築を行う
    - 「業務へ戻す」段階
- Lessons Learned（教訓整理）
    - 「なぜ防げなかったか」を振り返る工程
    - 再発防止が目的
    - 初心者ほどこの視点を忘れがち
- SIEM
    - ログを集約・分析する仕組み
    - 「全体監視センター」のような存在
    - 異常検知に強い
- EDR
    - 各端末を監視・防御する製品
    - 「PC内部を監視する監視員」イメージ
    - 最近のSOC運用では非常に重要
- Antivirus（AV）
    - 既知マルウェアを検知する基本防御
    - ただし未知攻撃には弱いこともある
- Playbook
    - インシデント対応手順書
    - 「この攻撃ならこの順番で対応する」を定義
    - 現場では非常に重要
- Runbook
    - Playbookよりさらに詳細な実行手順
    - 実際のコマンドや操作レベルまで落とし込む
- Incident Response Plan（IRP）
    - 組織全体のインシデント対応計画
    - 誰が何を担当するかを明確化
    - 技術だけでなく「連絡体制」も含む
- SANS PICERL
    - インシデント対応6段階モデル
    - Preparation → Identification → Containment → Eradication → Recovery → Lessons Learned
    - 初学者はまずこの流れを覚えると理解しやすい
- 「感染した端末」と「実行した端末」は違う
    - 添付ファイルを受信しただけでは即感染ではない
    - 実行されたかどうかが重要
    - フォレンジックではこの差が大きい
- 「まず隔離」が超重要
    - 調査したい気持ちより先に、被害拡大防止
    - SOC/CSIRT現場では最優先事項
- ログは最重要証拠
    - フォレンジックでは「証拠を読む仕事」が中心
    - ログが無いと何も分からない
    - 普段からログ取得設計が重要
- 人が最後に判断する
    - ツールは補助
    - SIEMやEDRが検知しても、最終判断はアナリスト
    - 「なぜ怪しいのか」を説明できることが重要
- サイバーセキュリティは「予防だけ」ではない
    - 「侵害される前提」で考える
    - 攻撃後にどう対応するかが Incident Response の本質
