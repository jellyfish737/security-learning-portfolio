## メモ **/ Notes**

#### Cryptography（暗号技術）

- 認証（Authentication）
    - 通信相手が本当に本人であることを確認する仕組み
- 真正性（Authenticity）
    - データが正しい送信者から送られたことを証明する仕組み
- 完全性（Integrity）
    - データが改ざんされていないことを保証する仕組み
- 機密性（Confidentiality）
    - 権限のない第三者による盗聴を防ぐ仕組み

---

#### Symmetric Encryption（共通鍵暗号）

- 送信者と受信者が同じ鍵を使用して暗号化・復号する方式
- 主な目的は機密性の確保
- 処理速度が速く、大量のデータ暗号化に向いている
- 鍵を安全に共有する必要がある

---

#### Asymmetric Encryption（公開鍵暗号）

- 公開鍵と秘密鍵のペアを利用する暗号方式
- 認証・真正性・完全性の実現に利用される
- 共通鍵暗号より処理は遅い
- 主な用途
    - 鍵交換
    - デジタル署名
    - 証明書

---

#### RSA

- 代表的な公開鍵暗号アルゴリズム
- 「大きな数の素因数分解が困難」であることを安全性の根拠としている
- 安全でない通信路でも安全に情報を送信できる

#### RSAで覚えるべき値（CTF頻出）

- p
    - 大きな素数
- q
    - 大きな素数
- n
    - p × q
- e
    - 公開指数
- d
    - 秘密指数
- Public Key
    - (n, e)
- Private Key
    - (n, d)
- m
    - 平文（元のメッセージ）
- c
    - 暗号文

#### CTFでのRSA

- 与えられたRSAパラメータから秘密鍵を求める問題が多い
- 素因数分解や数学的な弱点を利用して復号するケースがある
- よく使われるツール
    - RsaCtfTool
    - rsatool

---

#### Diffie-Hellman Key Exchange

- 安全でない通信路上で共有鍵を生成する仕組み
- 鍵そのものを送信せずに共通鍵を作成できる

#### 特徴

- 通信相手同士が同じ共有秘密鍵を生成できる
- 盗聴者は公開情報だけでは共有秘密を計算できない
- TLSやVPNなどで広く利用されている

#### 利用目的

- 共通鍵暗号で利用する鍵の生成
- セッション鍵の共有

#### RSAとの違い

- Diffie-Hellman
    - 鍵共有
- RSA
    - 認証・署名・暗号化

---

#### Digital Signature（デジタル署名）

- データの送信者を証明する仕組み
- ファイルの改ざん検知にも利用される

#### 確認できること

- 誰が作成したか（真正性）
- 改ざんされていないか（完全性）

#### 基本的な流れ

- 送信者がファイルのハッシュ値を作成
- ハッシュ値を秘密鍵で署名
- 受信者が公開鍵で署名を検証
- ハッシュ値を比較して改ざんの有無を確認

---

#### SSH Host Key Verification

- SSH接続時にサーバーの正当性を確認する仕組み

#### 初回接続時の警告

```
The authenticity of host can't be established.
```

#### 意味

- SSHクライアントがサーバーの公開鍵をまだ知らない状態
- 中間者攻撃（MITM）の可能性があるため確認を求める

#### 初回承認後

- サーバーの公開鍵フィンガープリントを保存
- 次回以降は同じ鍵であることを確認して接続

---

#### SSH Key Authentication

- パスワードの代わりに公開鍵認証を利用する方式

#### メリット

- パスワード認証より安全
- ブルートフォース攻撃に強い
- 自動化との相性が良い

#### 鍵生成

```
ssh-keygen
```

#### 接続

```
ssh-i private_key user@host
```

#### 公開鍵配置

```
ssh-copy-id user@host
```

#### 重要ポイント

- 秘密鍵は絶対に共有しない
- 公開鍵のみサーバーへ配置する
- 秘密鍵の権限は600以下に設定する

```
chmod600 id_rsa
```

---

#### SSH Key Algorithms

- RSA
    - 最も広く利用される公開鍵アルゴリズム
- DSA
    - デジタル署名専用アルゴリズム
- ECDSA
    - 楕円曲線暗号を利用した署名方式
- Ed25519
    - 高速かつ安全性の高い署名アルゴリズム
- ECDSA-SK / Ed25519-SK
    - ハードウェアセキュリティキー対応版

#### 実務でよく見るもの

- Ed25519
- RSA

---

#### authorized_keys

- SSH公開鍵認証を許可する公開鍵を保存するファイル

#### 保存場所

```
~/.ssh/authorized_keys
```

#### 用途

- ファイル内に登録された公開鍵のみSSHログインを許可する

---

#### Certificate（電子証明書）

- サーバーが本物であることを証明する仕組み
- HTTPS通信で利用される

#### 証明書で確認できること

- 接続先が本物のWebサイトであること
- 通信が暗号化されていること

---

#### Certificate Authority（CA）

- 証明書を発行する認証局

#### 役割

- Webサイトの身元確認
- 証明書への署名

#### 代表例

- Let's Encrypt
- DigiCert
- GlobalSign

---

#### Chain of Trust（信頼の連鎖）

- 証明書の信頼性を保証する仕組み

#### 流れ

```
Webサイト証明書
        ↓
中間CA
        ↓
ルートCA
        ↓
OS・ブラウザ
```

#### ポイント

- ブラウザは信頼済みルートCAを保持している
- 証明書が信頼の連鎖で検証できればHTTPS接続が成立する

---

#### Let's Encrypt

- 無料でTLS証明書を発行できる認証局
- 多くのWebサイトで利用されている

#### メリット

- 無料
- 自動更新可能
- HTTPS導入が容易
